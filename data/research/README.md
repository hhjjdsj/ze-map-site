# data/research/ —— 地图资料「原稿」

**要给某张地图补充或修正资料？改这个目录里的 JSON，不要改 `src/content/maps/` 下的 `.mdx`。**

## 为什么

仓库里有两个长得很像的东西：

| | 文件 | 是什么 |
|---|---|---|
| ✅ **原稿（改这里）** | `data/research/<地图英文名>.json` | 网站从它生成条目内容 |
| ❌ 打印稿（别改） | `src/content/maps/<地图英文名>.mdx` | 由脚本**自动生成**，改了会被覆盖 |

所有 `src/content/maps/*.mdx` 都由脚本生成，每次构建会从 JSON 和索引重新生成；写在 MDX 里的改动会被覆盖。

「地图英文名」= 地图页标题下面那行小字 = 网址里 `/maps/` 后面那一段（例如 `ze_flowering`）。

## 怎么改（网页上就能做，不用装任何东西）

1. 在这个目录里找到 `<地图英文名>.json`，点进去
2. 点右上角的**铅笔图标 ✏️**
3. 改下面这几个字段：

| 字段 | 说明 |
|---|---|
| `difficulty` | 难度。**只能填这七个之一**：`入门` `简单` `普通` `困难` `火星` `入土` `未知` |
| `summary` | 介绍正文。要分段就在段与段之间写「**一个**反斜杠 + n」两遍（在 JSON 里看起来就是 `\n\n`）。⚠️ 千万别写成**两个**反斜杠 —— 那样页面上会原样显示出一串 `\n\n`、不会换行 |
| `tags` | 标签数组，例如 `["剧情", "双结局"]`。成对的中括号、每个标签用英文双引号包起来、之间用英文逗号 |
| `videoUrls` | 视频链接数组，写法同上 |
| `sources` | 资料来源链接。**写了 `summary` 就必须至少给一条** |
| `confidence` | 资料可信度：`high` / `medium` / `low` |

4. 往页面下面拉，写一句「改了什么」，点绿色按钮 **Propose changes**
5. 下一页点 **Create pull request**

## 找到对应的 JSON

已收录地图大多有一个 JSON；新收录的地图如果还没有，请按地图英文名新建文件。没人整理过的文件通常是一份填空模板：

```json
{
  "_说明": "改这个文件就行。difficulty 只能填：入门/简单/普通/困难/火星/入土/未知；summary 写介绍正文……",
  "difficulty": "未知",
  "summary": null,
  "tags": [],
  "confidence": "low"
}
```

**你只要把想填的改掉，其余保持原样：**

- `difficulty` 拿不准就留 `未知`
- `summary` 把 `null` 换成 `"你的介绍正文"`
- `tags` 在方括号里加，例如 `["神器", "多关卡"]`；没有就留 `[]`
- `videoUrls` 有视频再加，没有就整个删掉

> **`difficulty` 是 `未知`、`tags` 是空数组，是完全正常的** —— 等价于「这条还没人定过」。真正有价值的是 `summary`（正文）和你确认得了的难度。

> **注意区分「改原稿」和「走投稿」**：`summary` 这类由资料整理的正文只能改 JSON；
> 而**神器 / 道具表**、**背景故事**、**封面图** 这类字段投稿页就能交 ——
> 交上来的内容进 `data/community/<slug>.json`，在条目页单独成块显示
> （背景故事进「背景故事（社区投稿）」，神器 / 道具逐行合并进表格），
> **不会覆盖**你写在这里的原稿。

## 还能换地图封面（要传图片文件）

地图封面默认是脚本从地图数据渲染的（俯视密度图 + 实体点）。觉得某张图有更好看的封面，可以换成自己的图。

这张图会同时出现在两个地方，所以**挑横向的**：地图库卡片（16:9 画幅）和详情页顶部（满宽背景大图，上面压了一层暗色遮罩）。

### 网页上怎么做（**推荐走投稿页，不用 GitHub 账号**）

最省事：地图详情页右侧栏 →「✏️ 补充这张图的资料」→「要提交哪一项」选 **地图封面** → 选图提交，
浏览器会自动裁成 16:9、压成 webp，审核通过并写回仓库后生效。

下面这条是「直接改文件」的路（提 PR），**必须先 Fork**：

⚠️ 你在这个仓库里没有写权限，**直接在目录里点「Add file → Upload files」会被 GitHub 拒绝**
（`You need write access to this repository`）。要先复制一份到你自己的账号下：

1. 仓库首页右上角 **Fork** → **Create fork**（得到 `你的用户名/ze-map-site`）
2. 在**你自己那份副本**里打开 `public/images/covers/custom/`
3. **Add file → Upload files**，把图片拖进去。**文件名必须正好是「地图英文名」**，例如 `ze_obj_abyss_v2.jpg`
   - 格式 `.jpg` / `.png` / `.webp` 都收。**但截图直接存 PNG 往往有 1~2 MB，会超限** ——
     尽量存成 JPG（画质 80 左右），或者用 `npm run cover:set` 让脚本压成 webp（通常只有 1/10）
   - ⚠️ **不是** Steam 分片名（`2001-ze_xxx-123456`）。名字写错这张图**永远不会显示**，而页面和构建全都正常，你不会收到任何报错
4. 拉到底 **Commit changes**（提交进你自己的副本）
5. 回到原仓库 → **Compare & pull request**（没看到就 **Contribute → Open pull request**）→ **Create pull request**

嫌麻烦就把图发给站长代传（站长跑 `npm run cover:set -- <地图英文名> <图片>` 会自动压好、文件名也帮你对上）。

### 图片要求

| | |
|---|---|
| 比例 | 尽量横向 16:9。竖图会被裁成中间一条（想保留完整画面可以找站长处理） |
| 宽度 | 1280px 左右最合适，至少 640px —— 详情页顶部会放大当背景 |
| 体积 | 尽量 300 KB 以内，**硬上限 800 KB**（超了 CI 会红） |

提了 PR 之后会自动跑一遍检查：**文件名对不上地图、格式不支持、体积超标**会直接标在 PR 页面上（`npm run cover:verify`，想在本机先试就自己跑一下）。

### 替换 / 删除

图片是二进制文件，GitHub 的**铅笔编辑改不了它**（只给文字文件用），但下面两件事都能在网页上做（同样在你自己 fork 的 `custom/` 里操作）：

- **换成另一张**：还是 **Add file → Upload files**，**文件名和路径保持一致**，就是覆盖
- **换回脚本渲染的封面**：在 `custom/` 里点开那张图 → 右上角 **⋯ → Delete file** → 提个小 PR。不需要改任何配置

> 网页上传单个文件上限是 25 MB，但封面这种网页资源没必要那么大 —— 我们的硬上限是 800 KB。

## 四个千万别碰

- ❌ **`summary` 这一行不能删**（暂时没内容就写 `null`）
- ❌ **`src/content/maps/` 下的 `.mdx`** —— 打印稿，改了白改
- ⚠️ **标签要照站内已有的写法**。比如是「传送门多」不是「传送多」，写岔了会凭空多出一个只有一张图的空标签页
- ⚠️ **分段别写成两个反斜杠**。段落之间是「一个反斜杠 + n」打两遍（`\n\n`）；写成两个反斜杠时页面会原样显示一串 `\n\n` 而不换行（`npm run content:verify` 会拦住这一种）

## 富内容条目

这三张地图的完整页面存放在对应 JSON 的 `document` 字段中，**也不要直接修改 `.mdx`**：

- `ze_ffvii_mako_reactor`
- `ze_lotr_minas_tirith`
- `ze_pirates_port_royal`

`document` 存储完整 MDX 源码（包括 frontmatter 和组件），由生成器直接写出；需要调整时修改 JSON 中的 `document`。

## 不想碰 GitHub？

用网站上的投稿表单：地图页右侧栏「✏️ 补充这张图的资料」。那个连 GitHub 账号都不用，填完进人工审核队列。

## 命令行（本机开发时）

```powershell
npm run maps:generate      # 从这些 JSON 重新生成 src/content/maps/*.mdx
npm run content:verify     # 校验这些 JSON（来源链接、难度枚举、可疑措辞等）
npm run content:rename-difficulty   # 批量改难度叫法（映射表见 shared/difficulty.mjs）
```

> 注：`npm run build` 现在已经包含 `maps:generate`，所以正常构建会自动重新生成，不用手动跑。
