# 神器 / 关卡教程（左图右文）怎么写

2026-10-09 起，地图条目支持**图文交错**的玩法讲解：神器机制、道具怎么用、关卡要点。
内容是**叠在自动正文之上**的，不会取代神器表、数据概况那些机器统计。

## 两条投稿路径

| 路径 | 谁来做 | 能用到 | 署名 |
|---|---|---|---|
| **投稿页**（推荐给玩家） | 任何人在 <https://ze-map.cn/submit/> 选「攻略 / 神器讲解」填写 | 图文块、图片集 | 页面显示「由 <昵称> 补充」 |
| **原稿**（`data/research/<地图名>.json` 的 `guides[]`） | 站长 / 会写 JSON 的人 | 图文块 + **神器表可点进讲解** | 人工稿，不走社区署名 |

两条路径的正文语法**完全一样**，玩家在表单里怎么写，原稿里就怎么写。

## 图文块的语法

```
:::figure 2             ← 引用图片集里的第 2 张图，图在左（默认）
这一段文字会排到图片的右侧，可以分多段。
Markdown 照常（**粗体**、`代码`、列表、链接都行）。
:::

:::figure 2 right       ← 图在右
文字在左。
:::
```

- 序号 = **这张图图片集里的顺序**，从 1 开始。图片集在条目底部，也可以在投稿页的「图片集图片」里一次传最多 24 张、每张写一句说明（那句说明就是图注）。
- 想左图右文，先有图：**先传图，再在正文里按序号引用**。
- 序号写错（图还没传、或数错了）**不会让页面报错**：只渲染文字，并在图上位置留一句提示，写明「当前共 N 张」。
- 手机端自动堆成上下；`right` 只影响桌面端左右顺序。

## 原稿怎么写（能点亮神器表）

```json
{
  "guides": [
    {
      "title": "神器：Push 怎么用",
      "body": "按左键推出僵尸，冷却 60 秒。\n\n:::figure 1 right\n第一段讲解……\n\n第二段讲解……\n:::\n\n收尾。"
    }
  ]
}
```

规则：

- `title` 里出现某件道具的名字 → **神器 / 道具表里那一行会变成链接**，点一下直接跳到这一节（表上方会多一句「带链接的道具名可以点进下面的教程」）。
- 一节讲多件道具？标题里都写上就行（表里对应几行都会链到同一节）。
- 多节按数组顺序排，排在哪：自动正文的**神器表之后**、数据概况之前；手写整篇的图（`sections`）排在手工小节之后。
- 校验由 `npm run content:verify` 把关：`guides` 只能有 `title` / `body` 两个字段，都不能为空。

## 一句话说明（每张图的「全神器总览」）

除了长文讲解，每件神器还能写**一句话说明**：填进同一份原稿的 `relicIntros` 对象。

```json
{
  "relicIntros": {
    "Push": "把人或僵尸推开的起手神器，冷却 60 秒，适合开局抢位。",
    "Wall": "在身前立一道墙挡僵尸，冷却 60 秒。"
  }
}
```

### 也可以用投稿页改（推荐给玩家）

投稿页选「神器 / 道具」后：

- 上面会列出**这张图现在的神器表**，**点一件**就把它的名字 / 冷却 / 次数 / 说明带进下面的行里 —— 改「原有神器的说明」不用再凭记忆打名字（以前名字打错一个字符就会被当成「新增一件」）。
- 每行有**两个不同的输入框**：**说明** = 神器表那一列的「这件神器是干嘛的」（≤200 字）；**备注** = 我们服和原表的差别（例如「第四关才刷」）。冷却 / 次数留空 = 这一项不动。
- 名字对得上表里已有的算「更正」，对不上算「新增」，勾「本图没有这件」算「删除」—— 动作仍由名字决定，投稿人不用选。
- 审核通过后写进 `data/community/<地图>.json` 的 `items[]`（带 `intro`），生成器合并时**社区说明优先于原稿说明**（和神器表其它列的规则一致）。
- 审核台会把「说明 / 备注 / 提交人」分开列出来，避免审核员分不清投稿人是在介绍神器还是在说本服参数。

- 神器表会因此**多出一列「说明」**：写了的显示说明，没写的显示「待补充」；标题里出现了这件道具的 `guides` 小节会在同行挂一个「详细 ↓」锚点。
- **一张图里只要有人写过一句（或有 `guides` 小节），这一列才出现** —— 什么都没写的图，表格保持原样，不会整站多出一列「待补充」。
- 说明超过 200 字会被 `content:verify` 拦下：这里是一句话，长文写进 `guides`。

### 谁来写、怎么不写漏

```bash
node scripts/content/relic-intro-todo.mjs                 # 进度：多少图 / 多少件神器还没写
node scripts/content/relic-intro-todo.mjs --map ze_castlevania   # 打印这张图可直接填的骨架
node scripts/content/relic-intro-todo.mjs --write         # 导出勾选清单 data/relic-intros.todo.md
```

2026-10-09 的起点：站内有神器数据的图 **193 张 / 1609 件神器，说明 0 件**。
清单按图列出每件神器的名字与「是否已有讲解」，可以当工作清单逐图推进。
`data/relic-intros.todo.md` 是生成物（在 `.gitignore` 覆盖的 `data/` 下），随时重跑即可。

## 录制视频的说明

进阶跑图、手电这类「手感经验」不适合写成图文 —— 条目里已有「攻略视频」字段（投稿页可填 B 站链接，页面直接内嵌播放），
视频想放站上就填这个字段，不想放也不影响图文教程。
