## 那个目录里是什么

| 东西 | 大小 | 说明 |
| --- | --- | --- |

## 关键结论：实体数据我们早就有，缺的是地形

解开 `preview3d.html` 里那行 `H4sI...`（base64 → gzip → 38 MB）后，开头是：

```json
{"meta":{"built":"2026-09-23 13:04","maps":645,"entities_all":629562,
 "source":"…（第三方服务端实体 dump，字符已隐去）", ...}}
```

**和本站实体数据同源、同快照**（我们生成的 MDX 注释里写的就是「快照 2026-09-23 13:04」）。
所以这个软件里**唯一我们还没有的东西就是 `terr/` 的真实碰撞地形**。

数据块自己的格式（`loadPayload()`）：

```
base64(gzip)  →  [u32 LE: JSON 长度][JSON][剩余 = 底图位图 + 雷达 webp]
```

## terr/<工坊ID>.bin 格式（已逐字节验证）

```
gzip( MSH1 头 + 量化顶点 + 索引 )
  偏移 0   : 'MSH1'                 魔术字
  偏移 4   : uint32 LE  nv          顶点数
  偏移 8   : uint32 LE  nt          三角面数
  偏移 12  : uint32 LE  u16i        1 = u16 索引，0 = u32 索引
  偏移 16  : float32 LE × 3         原点 o（源坐标）
  偏移 28  : float32 LE × 3         缩放 s
  偏移 40  : nv × 3 × uint16        量化顶点（每轴 u16）
  随后     : nt × 3 × (u16 或 u32)  索引
```

验证（`node` 直接解包）：3 个样本全部 `40 + nv*3*2 + nt*3*(2|4) === 解压长度`，**完全吻合**，索引无越界。

| 样本地图 | 压缩 | 解压 | 顶点 | 三角面 |
| --- | --- | --- | --- | --- |
| ze_2049 视觉盛宴 | 408 KB | 757 KB | 57,193 | 72,000 |
| ze_2012_p 方舟2012 | 426 KB | 695 KB | 46,583 | 72,000 |
| （另一个样本） | 455 KB | 739 KB | 54,091 | 72,000 |

量化顶点的还原公式写在它的着色器里（`setMesh()` 把顶点展开成每顶点 12 字节的交错缓冲：
3×u16 位置 + 3×i8 法线 + 2 填充，法线按三角形平面现算），移植时照抄即可。

## 本站现状（差在哪）

`/preview/` 本来就是同一个单文件版的移植（`public/preview/app.js`，60 KB，WebGL），
三维视图渲染的是**实体点 / 盒子 / 连线**（`setPoints` / `setBoxes` / `drawLines` / `init3D` / `build3D`），
**没有地形网格**（全文件里「地形」只出现在 2 处无关注释里，函数表里没有 `setMesh` / `loadMesh`）。

所以「更新所有地图的 3D 模型」= 把地形管线补上，接点清晰：

| 要移植的 | 来源函数 |
| --- | --- |
| 载入分包 | `terrScript(wf)` / `terrBytes(wf)` |
| 解码网格 | `loadMesh()`（读 MSH1 头、解压、切分 verts/idxs） |
| 上载 GPU | `setMesh(verts, idxs, o, s, nt)` |
| 画地形 | 着色器 + 绘制调用（在 `render3D` 里） |
| 图层开关 | `refreshMeshRow()` / `clearMesh()` |
| 是否可用 | `meshAvail(m)`（软件里看记录上的 `wm` 标记） |

## 两个必须先定的事

### 1. 授权（唯一需要你拍板的）

`terr/` 是第三方用 Source 2 Viewer 从创意工坊地图包里解析出来的几何数据，
随「云朵小铺」这个社区工具分发。**把它放进本站 = 二次公开发布**，需要：

- 「云朵小铺」作者的同意（除非你就是作者 / 已获得许可）
- 保留 Source 2 Viewer 的署名（它的许可要求署名，软件自己也标了「Powered by Source 2 Viewer」）
- 地图几何的版权仍属各图原作者 —— 本站现有的「地图版权归原作者，本站只做整理」表述要相应补充

### 2. 体积方案

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| A. 全量进 `public/terr/`（545 个文件，183.8 MB） | 最省事，和现有 `/preview/` 同一套静态加载；645 个文件远低于 Cloudflare 20,000 上限，单文件 ≤670 KB 远低于 25 MiB | 仓库 +184 MB，**每次 Cloudflare 构建都要克隆一遍** |
| B. 放 Cloudflare R2 | 构建不受影响；R2 免费额度 10 GB、零出口费 | 要配域名/路由，多一处基础设施 |
| C. 只放有攻略资料的那批 | 体积小（约 35 MB） | 与「所有地图」的目标不符 |

倾向：**先 A 全量**（按需加载，单次访问只拉一张 ~400 KB），构建如果变慢再迁 B。

## 关键实现细节

- **还原公式**：`world = o + q × s`（q 为 u16 量化值），轴向 `(x, z, -y)` 把 Source 的 Z 朝上转成 GL 的 Y 朝上 —— 与站上实体数据同一套变换，所以地形和实体块体天然对齐。
- **法线**：原始数据没有法线，按三角形平面现算并量化成 i8（`gl.BYTE, normalized`）。
- **去索引**：`setMesh` 按三角形展开成 12 字节/顶点的交错缓冲，走 `drawArrays`。既和块体共用绘制路径，也绕开 WebGL1 下 u32 索引需要扩展的问题。
- **缓存 Promise 而不是结果**：进 3D 与切图会几乎同时触发两次刷新，缓存结果会让同一个分包被下载两遍（实测 408 KB × 2），改成缓存进行中的 Promise 后为 1 次。
- **优雅降级**：分包缺失（快照之后上架的新图）或解压失败时只清空网格，状态显示「本地无地形」，实体照常显示。
