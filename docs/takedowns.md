# 下架记录（按作者 / 社区要求删除的内容）

**为什么单独记一份**：站上的内容随时可能因为「作者不希望被收录」「社区有意见」而下架。
删掉之后，如果不留记录，过一阵子没人说得清「这张图为什么没有」、也分不清是漏收录还是被要求下架；
反过来，这份记录也是我们**配合作者与社区**的证据 —— 有人来问，直接看这里。

规则（2026-10-09 起）：

- 作者或社区提出 → **立即下架，不争论**；需要保留解释的，写在这里。
- 下架范围要**连根拔**，别只删页面：条目（`src/content/maps/`）、原稿（`data/research/`）、
  实体分片（`public/entity/data/`）、地形分片（`bake/terr/` + R2 对象、`data/terr-manifest.json`）、
  封面（`public/images/covers/`）、图片集清单（`data/gallery/`）、工坊资料（`data/workshop/`）、
  体积数据（`npm run data:sizes`）、以及 `public/entity/catalog.json` 里的条目
  （⚠️ `build-catalog.mjs` 会保留历史条目，**光删分片不够**，必须同时剪索引）。
- 如果该图已被链接到（例如写进了某条攻略），构建时的 `npm run content:links` 会报死链 —— 一并清掉。
- 下架前把删掉的文件备份一份到仓库外（`%TEMP%\bak-*`），万一聊清楚要恢复，不用重新烘。

### 视频（2026-10-10 补）

视频是**嵌入**不是转存：条目里用的是 bilibili / YouTube 的官方播放器，视频文件一直在原平台，
本站没有副本，播放量与收益也留在原平台。所以：

- 视频**署名以原平台为准**，条目里保留「在原站打开 ↗」的回链，这是引用的前提，不许去掉。
- 作者（或 UP 主）说**不希望被收录** → 从原稿 `data/research/<slug>.json` 的 `videoUrls`、
  `sections` 正文、以及社区文档 `data/community/<slug>.json` 的 `videoUrls` 里删掉那条链接，
  再 `npm run maps:generate`。**不需要**因此下架整张地图（除非作者要求的是整张图）。
- 反过来：**永远不要**把视频下载下来放进仓库或 R2。一旦转存，「引用」就变成「复制」，
  这是这条规则里唯一的红线。社区投稿带来的视频链接同样受这条约束。

### 图片（2026-10-10 补）

封面（`public/images/covers/`）与图片集（清单 `data/gallery/`，图片在 R2 `gallery/` 前缀）
是**转存的展示用图**，和视频不是一回事 —— 它们是副本，所以更要按「要求即撤」办：

- 只收：作者在创意工坊公开的预览图、投稿人自己的游戏内截图。
- 收到要求 → 删封面文件（含 `data/community/<slug>.json` 里那条 `cover` 字段，否则页面还会指向它）、
  删图片集清单里的条目 **并同时删 R2 对象**（`npx wrangler r2 object delete ze-map-terr/gallery/<slug>/<文件名> --remote`），
  清单留着指向不存在的图会变成坏图。
- 封面被撤后可以退回工坊图或渲染兜底图；投稿的图被撤后直接从清单里移除，不用补。
